카메라가 움직여도, 템플릿은 다시 만들지 않는다

템플릿은 teaching 시점에 한 번 정의된다. 런타임 카메라가 이동해도 매칭이 상대포즈를 매 프레임 새로 구하므로 anchor는 계속 추정된다. 카메라 이동분은 cam_to_base 한 값으로만 흡수한다.

Δ = 1000 mm · anchor 오차 0 mm 판정 OK — anchor가 세이프존 안
teaching 카메라 (고정) runtime 카메라 (이동) anchor 참값 anchor 추정값 세이프존 (base 고정)

슬라이더로 runtime 카메라를 옮겨 보세요. cam_to_base 갱신이 켜져 있으면 카메라가 어디로 가든 추정 anchor(점선 원)는 참값 위에 그대로 겹칩니다. 꺼 보면 — 옛 캘리브레이션으로 base에 매핑되는 바람에 추정값이 카메라 이동량만큼 끌려가 세이프존을 벗어나고, 정상 부품이 NG로 오검됩니다.

동작 흐름 — 무엇이 고정이고, 무엇이 매번 새로 구해지는가

STEP 1고정

템플릿 (teaching)

기준 RGB/depth, anchor 정의점(selected_points), base 세이프존, teaching cam_to_base. 한 번 만들고 다시 손대지 않는다.

STEP 2매 프레임

매칭 → 상대포즈

RoMa V2가 템플릿과 현재 화면의 대응점으로 3D 상대포즈(4×4)를 구한다. "이 객체가 지금 카메라에서 어디에·어떤 자세로 보이나" — 카메라의 절대 위치와 무관하다.

STEP 3매 프레임

anchor 추정

템플릿의 anchor 정의점에 상대포즈를 적용 → 현재 카메라 프레임의 anchor 3D. 카메라가 어디에 있든 새로 산출된다.

STEP 4base 판정

base 매핑 · 세이프존 검사

anchor는 runtime cam_to_base로, 세이프존은 teaching cam_to_base로 base에 올려 비교한다. 세이프존은 base에 고정.

카메라가 재배치되어도 템플릿을 다시 만들 필요가 없다. 바뀐 것은 카메라→로봇 관계(cam_to_base) 하나뿐이며, 그 값만 갱신하면 매칭이 상대포즈로 anchor를 계속 정확히 추정한다. 갱신하지 않으면 — 위 다이어그램의 토글이 보여주듯 — 정상 부품이 NG로 오검된다.
